# ТЗ: Фильтр отображения GPX-трека по временно́му диапазону

**Проект:** GPXSee (форк `GlucoPlan/GPXSee`)
**Дата:** 2026-10-17
**Статус:** реализовано (2026-10-18)

## 1. Цель

Дать пользователю возможность при просмотре трека(ов) задать абсолютный
временно́й диапазон (дата+время начала и дата+время конца) и видеть на экране
только те точки, время которых попадает в этот диапазон. Фильтр влияет
одновременно на карту, графики и статистику. Исходные данные не изменяются.

## 2. Исходные данные (как есть в коде)

- Каждая точка `Trackpoint` хранит метку времени `timestamp()` (`QDateTime`),
  если в GPX присутствует тег `<time>`. Наличие проверяется `hasTimestamp()`.
- Трек: `Data → tracks() → Track → TrackData` (список сегментов
  `QVector<Trackpoint>`).
- Отрисовка идёт через `GUI::loadData(const Data&)`:
  - графики строятся вкладками `_tabs[i]->loadData(...)`;
  - линия на карте — `_mapView->loadData(...)` → `PathItem`;
  - статистика (расстояние/время/движение) суммируется там же.
- Уже есть переключатель оси графика «расстояние / время» (`GraphType`) и
  слайдер-маркер положения. Готового фильтра по диапазону нет — это новая
  функция.
- Учитывается часовой пояс приложения (`_options.timeZone`).

## 3. Функциональные требования

### 3.1. Выбор диапазона (UI) — два способа, синхронно

1. **Поля ввода «С» и «По»** — дата + время каждое. Для точного задания границ.
2. **Два перетаскиваемых маркера** на отдельной временно́й шкале в панели
   фильтра. Шкала охватывает полный абсолютный интервал всех открытых треков.
   *Изменение при реализации:* маркеры вынесены из области графика, т.к. ось
   графика GPXSee — это время от старта каждого трека (или расстояние), а не
   абсолютное время, и для общего диапазона нескольких треков не подходит.
3. Поля и маркеры **синхронизированы в обе стороны**: правка поля сдвигает
   маркер и наоборот.
4. Границы диапазона — **включительно** (`С ≤ t ≤ По`).
5. Время задаётся и отображается в текущем часовом поясе приложения
   (`_options.timeZone`).

### 3.2. Область действия диапазона

- Диапазон **единый абсолютный** для всех открытых треков (общая ось
  реального времени, не относительная к старту каждого трека).
- Точка видна тогда и только тогда, когда `С ≤ timestamp ≤ По`.

### 3.3. На что влияет фильтр (всё синхронно)

- **Карта:** линия трека (`PathItem`) рисуется только по видимым точкам.
  Если выброшены промежуточные точки — трек визуально «обрывается» на границах
  интервала; это допустимо (показываем только выбранный отрезок).
- **Графики:** все типы (высота, скорость, пульс, каденс, мощность,
  температура, передачи) строятся только по видимым точкам.
- **Статистика:** расстояние, время, время в движении, средние/макс. —
  пересчитываются по видимым точкам.

### 3.4. Значения по умолчанию

- При открытии файла(ов) диапазон = полный интервал: от минимального до
  максимального `timestamp` среди всех треков, имеющих время. Фильтр по факту
  ничего не скрывает, пока пользователь не сузит границы.

### 3.5. Треки без меток времени

- Если **ни один** открытый трек не содержит меток времени — контрол фильтра
  **недоступен** (disabled), треки показываются целиком.
- Если время есть **хотя бы у одного** трека — контрол доступен. Треки без
  времени при этом **не фильтруются** и показываются целиком независимо от
  выбранного диапазона.

### 3.6. Недеструктивность и сброс

- Фильтр — режим отображения, а не правка данных. Исходный `Data`/`Track` не
  меняется.
- Есть **переключатель вкл/выкл** фильтра и **сброс** к полному диапазону.
- Отключение/сброс возвращает полное отображение.

## 4. Нефункциональные требования

- Перетаскивание маркеров должно давать отклик без заметных подтормаживаний на
  больших треках (десятки–сотни тыс. точек). При необходимости — троттлинг
  пересчёта во время перетаскивания, финальный точный пересчёт по отпусканию.
- Фильтрация — по возможности через индексы/маску видимости, без полного
  переразбора файла на каждое движение.

## 5. Ориентир по реализации (архитектура — уточняется на этапе кода)

Затрагиваемые узлы:
- **Новый UI-контрол**: поля дата-время (С/По) + два маркера на `GraphView`
  (рядом со шкалой времени). Возможное размещение — панель над областью
  графиков или строка в тулбаре.
- **Слой фильтрации**. Два возможных подхода, выбор — в начале реализации:
  - (а) строить отфильтрованный `Data` и переиспользовать существующий
    `loadData` путь;
  - (б) хранить полные данные, применять маску видимости к `PathItem` и графикам
    без полной перезагрузки.
  Подход (б) предпочтительнее по производительности при частом перетаскивании.
- **Статистика**: пересчёт сумм, которые сейчас считаются в `GUI::loadData`, по
  видимому подмножеству точек.
- Активация контрола завязана на `Trackpoint::hasTimestamp()` по открытым трекам.

## 5а. Как реализовано

- **Фильтрация** — `Data::processData()` (`src/data/data.cpp`): перед
  построением `Track` точки вне `[С; По]` отбрасываются (`Data::filterTrack`).
  Поэтому карта, графики и статистика считаются по отфильтрованным точкам без
  изменений в их коде. Полный диапазон времени файла — `Data::timeRange()`
  (по нефильтрованным данным). Настройка фильтра —
  `Data::setTimeFilter(enabled, from, to)`, null-граница = без ограничения.
- **Применение** — через штатный `GUI::reloadFiles()` (тот же путь, что
  «Перезагрузить»); файлы на диске не меняются.
- **Панель** — `TimeFilterBar` (`src/GUI/timefilterbar.*`, тулбар «Фильтр по
  времени» отдельной строкой): галка, поля С/По (формат `дд.ММ.гггг чч:мм:сс`,
  календарь), шкала `TimeRangeSlider` (`src/GUI/timerangeslider.*`), «Сброс».
- **Точность полей** — 1 с: «С» = начало секунды, «По» = конец секунды
  (включительно). Шкала работает с точностью до мс.
- **Отклик** — при перетаскивании поля обновляются сразу, перезагрузка данных —
  по отпусканию ползунка; правка полей применяется с задержкой 0.5 с.
- **Пока диапазон не сужен**, фильтр с включённой галкой ничего не скрывает,
  а при открытии новых файлов границы расширяются автоматически. Сужённый
  пользователем диапазон при открытии новых файлов сохраняется.
- **Сброс фильтра** (галка снимается) при «Закрыть» / «Закрыть всё» и при
  переходе к другому файлу кнопками навигации — это уже другие данные.
- **Часовой пояс** — поля показывают время в поясе из настроек GPXSee и
  обновляются при его смене.
- **Перевод** — русские строки добавлены в `lang/gpxsee_ru.ts`.
- Только для настольных сборок (на Android панель не создаётся).

## 6. Вне рамок (сознательно не делаем сейчас)

- Экспорт/сохранение выбранного отрезка в отдельный `.gpx` (только отображение).
- Относительные диапазоны (от старта трека).
- Разные базы времени для разных треков (сейчас — единый абсолютный диапазон).

## 7. Критерии приёмки

1. Открыт GPX с временем → доступен контрол с полями С/По и маркерами; по
   умолчанию показан весь трек.
2. Сужение диапазона (полями или маркерами) → на карте, графиках и в статистике
   остаются только точки внутри `[С; По]`, синхронно.
3. Поля и маркеры синхронизированы в обе стороны.
4. Сброс/выключение → полный трек снова виден целиком.
5. GPX без времени → контрол недоступен, трек виден целиком.
6. Несколько треков с временем → один абсолютный диапазон применяется ко всем;
   трек без времени среди них показывается целиком.
7. Исходный файл на диске не изменяется.
